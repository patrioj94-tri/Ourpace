Part one · on your phone

Try it now

This is the preview: the whole 40-week plan, your real Strava history, and everything you tap is saved. It is yours only — Jean cannot open this one, and it has no live Strava. Part two fixes both.

  1. Open the link above in Safari — this does not work in Chrome on iPhone.
  2. Tap the Share button (the square with the arrow, at the bottom).
  3. Scroll down and tap Add to Home Screen.
  4. Name it Our Pace and tap Add.

Part two · on a laptop

Build the real one

About an hour · free

The real app adds the things a preview cannot have: Jean signs in too, Strava pushes every session the moment your watch uploads, and both Google calendars merge into the week.

Do this on a laptop, not your phone. There are about ten keys to copy between websites, and that is miserable on a phone. You will only need the phone again at the very end.

Never paste a key into this page, or into any chat. Keys go straight from the site that gave them to you into Vercel's settings, and nowhere else.

  1. Go to supabase.com and sign up with GitHub. Free, no card.
  2. New project. Call it our-pace, choose region Frankfurt (closest to Belgium), and let it generate a database password — save that password somewhere.
  3. Wait about two minutes while it builds.
  4. Open SQL Editor in the left sidebar. Open the file supabase/migrations/0001_init.sql from the repo, copy all of it, paste, and press Run. It should say success.
  5. Open supabase/seed.sql. Replace the placeholder with Jean's real email address — that line is the only thing that lets him in. Then paste it into the SQL Editor and Run.
  6. Go to Project Settings → API and keep that tab open. You need three values from it in step 4.

The service_role key on that page bypasses every security rule. It goes into Vercel and nowhere else — never into a browser, a chat, or a commit.

One Google app does both jobs: proving who you are, and reading your calendars.

  1. Go to console.cloud.google.com and create a project called our-pace.
  2. Search for Google Calendar API and press Enable.
  3. Go to APIs & Services → OAuth consent screen. Choose External, fill in the name and your email, and under Test users add both of your Gmail addresses.
  4. Credentials → Create credentials → OAuth client ID → Web application.
  5. Under Authorised redirect URIs add these two now (the third comes in step 5):
https://YOUR-PROJECT.supabase.co/auth/v1/callback
http://localhost:3000/auth/callback

Replace YOUR-PROJECT with your real Supabase project address.

  1. Copy the Client ID and Client secret.
  2. Back in Supabase: Authentication → Providers → Google. Turn it on and paste the same two values there. Save.

You do not need to publish the app or pass Google's verification. Test users work forever, and there are only two of you.

Garmin needs no setup at all. Garmin already pushes every activity to Strava, and Our Pace reads Strava. Garmin's own API is closed to projects this size, so this is the route that works, not a compromise.

  1. Both of you: open Garmin Connect → Settings → Connected Apps → Strava and connect, if you have not already. Yours is already done.
  2. Go to strava.com/settings/api and create an application. Any name. For Authorization Callback Domain put localhost for now.
  3. Copy the Client ID and Client Secret.
  4. Invent a random password-like string and write it down. That is your webhook token — it just has to match in two places.
  1. Go to vercel.com and sign in with GitHub.
  2. Add New → Project, and import patrioj94-tri/Ourpace.
  3. Under branch, choose claude/our-pace-app-planning-6kwo40.
  4. Open Environment Variables and add these. Names must match exactly:
NEXT_PUBLIC_SUPABASE_URLSupabase → Settings → API → Project URL
NEXT_PUBLIC_SUPABASE_ANON_KEYthe same page, the anon public key
SUPABASE_SERVICE_ROLE_KEYthe same page, the service_role key
NEXT_PUBLIC_SITE_URLput https://ourpace.vercel.app for now; you will correct it below
GOOGLE_CLIENT_IDfrom step 2
GOOGLE_CLIENT_SECRETfrom step 2
STRAVA_CLIENT_IDfrom step 3
STRAVA_CLIENT_SECRETfrom step 3
STRAVA_WEBHOOK_VERIFY_TOKENthe random string you invented
CRON_SECRETanother random string you invent
ANTHROPIC_API_KEYoptional — only for the Sunday note
  1. Press Deploy and wait a couple of minutes.
  2. Vercel gives you a real address. Go back to Environment Variables, correct NEXT_PUBLIC_SITE_URL to that exact address, then Redeploy. Sign-in will not work until this is right.
  1. Google: back in Credentials, add a third redirect URI — your real address followed by /auth/callback.
  2. Strava: change Authorization Callback Domain from localhost to your real domain, with no https:// and no path. Just the domain.
  3. Register the webhook. This is what makes sessions tick themselves off. Run this in a terminal, filling in your three values:
curl -X POST https://www.strava.com/api/v3/push_subscriptions \
  -F client_id=YOUR_STRAVA_ID \
  -F client_secret=YOUR_STRAVA_SECRET \
  -F callback_url=https://YOUR-APP/api/strava/webhook \
  -F verify_token=YOUR_VERIFY_TOKEN

It replies with an id. Strava calls your app back to check it is really yours, which is why this has to come after the deploy.

  1. Open your app's address and sign in with Google. That first sign-in creates your profile. Have Jean do the same on his phone — or wait, if he is not meant to know yet.
  2. Go to Settings inside the app and press Connect Strava. Say yes. It pulls in your last month straight away.
  3. Load the 40-week plan. On your laptop, with the repo cloned:
git clone https://github.com/patrioj94-tri/Ourpace.git
cd Ourpace
git checkout claude/our-pace-app-planning-6kwo40
npm install

export NEXT_PUBLIC_SUPABASE_URL=...
export SUPABASE_SERVICE_ROLE_KEY=...
node scripts/load-plan.mjs plans/malaga-70.3.csv

Both of you must have signed in before this, or it will not know who to give the sessions to. It will tell you so rather than guess.

Part three · both phones

Install the real one

1 minute each

  1. Open your app's real address in Safari on the phone, and sign in.
  2. Share → Add to Home Screen → Add.
  3. Delete the preview icon from part one — you do not need two.
  4. Go for a run. By the time you are home, it should have ticked itself off.

When something does not work

  • "Our Pace is private" on sign-in. That email is not in allowed_emails. Re-run seed.sql with the right address.
  • Sign-in loops, or lands on an error. Almost always NEXT_PUBLIC_SITE_URL not matching the real address, or a missing redirect URI in Google. Both must be exact, including https://.
  • Sessions never tick themselves off. Check Settings shows Strava connected. Then press Check Strava now — if that works but new sessions do not appear on their own, the webhook did not register; re-run the command in step 5.
  • The calendar is empty. Google only hands over calendar access on a fresh consent. Sign out and back in.
  • The week is empty. The plan starts 4 January 2027. Before then there is nothing to show — that is correct, not broken.

Everything here is also written down in SETUP.md in the repository, in case you would rather read it there.
